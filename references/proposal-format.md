# 开题报告写作格式规范

在撰写、修改或转换开题报告、研究方法与技术路线、选题依据、开题 LaTeX 内容时加载本文件。引用格式另见 `citation-style.md`。

## 封面与换页

- 使用学校开题报告样表对应的连续两页封面，后接目录。
- 不使用论文模板默认生成的中英文首页。
- 封面填写日期只出现在第一页底部，第二页说明页顶部不得重复出现填写日期。
- 开题报告不按双面论文方式插入空白页；LaTeX 入口应避免 `\cleardoublepage` 在封面、目录和正文之间产生空白页。
- 图按全文出现顺序编号，显示为“图 1”“图 2”等，不使用论文正文按章编号的“图 4.1”或“图4-1”格式。

## 内容结构

### 一、简况

- 包括题目、摘要和关键词。
- 不设置简况表格，除非学校样表明确要求。
- 关键词数量为 3-5 个；中文主题词之间空一格，英文关键词用 ` / ` 分隔。

### 二、选题依据

- `1.1` 标题固定为“选题背景和应用价值”。
- 说明选题背景、工程应用价值和本课题要解决的问题。
- 国内外概况和发展趋势按 `1.2.x` 分点组织；每一点下可分为 `1.2.x.1 国外研究现状` 和 `1.2.x.2 国内研究现状`。
- 国内外研究现状通常控制在 2-3 页左右，突出代表性技术和研究脉络，不堆砌全部文献。
- 说明选题的先进性和实用性，但必须落到工程对象、技术矛盾、应用价值和可验证目标。
- 技术难度及工作量要客观分析，说明难点在哪里、为什么需要相应工作量、哪些部分由本人完成。
- 本部分附主要参考文献，格式按论文参考文献要求。

### 三、研究的创新之处

- 可按学校要求留空或选填。
- 如果填写，采用谨慎口径，写清“本文工作”的新增设计、集成方式、验证范围或工程实现特点。
- 不把成熟技术、框架、协议或第三方工具的既有能力写成创新。

### 四、研究方法与技术路线

建议包含以下内容：

1. 课题内容：分点概述要完成的系统、模块、方法和验证工作，几句话即可，不写成长篇实现说明。
2. 系统需求分析：使用软件工程专业描述工具，例如 UML 用例图、业务流程图、活动图或用例描述；结构与论文第 3 章需求分析一致，但可省略“需求导出”的完整展开。
3. 系统概要设计：使用组件图、部署图、数据流图、顺序图、E-R 图等描述总体方案；结构与论文第 4 章概要设计一致。
4. 拟采用的设计方法、环境等：说明开发方法、技术栈、协议、框架、数据库、运行环境和测试环境。
5. 技术难度及特色分析；实践方案的可行性分析：区分难点、特色和可行性依据，避免泛泛评价。
6. 本人主要工作描述：列出本人承担的核心设计、实现、集成、测试和文档工作。

## 写作口径

- 开题报告用于论证“为什么做、做什么、怎么做、是否可行”，不是最终论文实现细节汇编。
- 研究现状可比论文正文更压缩，但仍应按文献、标准、协议、工程实践的脉络组织。
- 项目已采用的关键技术也应进入调研链路：补充该技术和同类技术资料，再写入国内外概况、相关技术说明或技术路线选型依据。
- 技术路线应体现从需求到架构、从架构到实现、从实现到测试验证的闭环。
- 可行性分析要写已有资料、技术基础、开发环境、实验条件和工作计划，不写空泛保证。
- 本人主要工作要与后续论文主要工作一致，避免承诺无法实现或无法验证的内容。

## 与论文的对应关系

| 开题报告部分 | 论文对应材料 |
| --- | --- |
| 选题背景和应用价值 | 第 1 章绪论背景与意义 |
| 国内外概况和发展趋势 | 第 1 章国内外研究和有关技术现状 |
| 课题内容 | 第 1 章本文主要工作 |
| 系统需求分析 | 第 3 章需求分析 |
| 系统概要设计 | 第 4 章系统概要设计 |
| 技术难度及特色分析 | 第 1 章主要工作、第 4/5 章设计说明 |
| 本人主要工作描述 | 第 1 章主要工作、第 7 章总结 |

## 检查清单

- 封面、目录和正文之间没有多余空白页。
- 图编号为全文顺序编号。
- 研究现状中没有把本文方案提前写入现有研究小结。
- 技术难度、特色和可行性分别成段或分点表达。
- 参考文献在正文中有引用，且列表编号按首次引用顺序排列。
- 技术路线图、用例图、架构图和 E-R 图等图件有正文引导和图题。
